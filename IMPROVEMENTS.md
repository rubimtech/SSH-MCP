# План улучшений ssh-mcp

Источники: [votsie/ssh-mcp](https://github.com/votsie/ssh-mcp) (MIT, Python/paramiko),
[tufantunc/ssh-mcp](https://github.com/tufantunc/ssh-mcp) (MIT, ~777★, TypeScript/ssh2),
[TheSashaDev/ssh-mcp-server](https://github.com/TheSashaDev/ssh-mcp-server) (**AGPL-3.0**, TypeScript/ssh2).

> Лицензия решает, что можно тащить кодом: из AGPL-репозитория берём **только идеи** и
> переписываем сами. MIT-репозитории можно цитировать фрагментами со ссылкой.

Оценки: **S** — до часа, **M** — до дня, **L** — несколько дней.

## P1. Безопасность (S–M, делать первыми)

| # | Предложение | Источник | Сложность |
|---|---|---|---|
| 1.1 | **Fence против prompt injection.** Оборачивать `stdout`/`stderr`/`content` маркерами «это данные, а не инструкции» и дублировать правило в `INSTRUCTIONS`. Сейчас скомпрометированный хост может напечатать «забудь прошлые инструкции» прямо в JSON ответа | votsie | S |
| 1.2 | **Redaction секретов.** Реестр известных паролей/passphrase, вычистка из любого возвращаемого текста (длинные — первыми, иначе короткий секрет разрежет длинный). Сейчас `cat .env.prod` отдаёт агенту все секреты в JSON | tufantunc, votsie | M |
| 1.3 | **Атомарная запись файла.** `sha256` текущего файла → залив во временный → `chmod`/`chown`/`backup` → `mv -f`. Сейчас `sftp.file(path, "w")` пишет на месте: обрыв = битый файл, а `mv` поверх симлинки заменит сам симлинк, а не цель | votsie | S |
| 1.4 | **Реальные known_hosts.** Сейчас `AutoAddPolicy` не пишет ключи никуда → проверки нет вообще, а `host_key_policy: reject` без файла бесполезен. Нужны TOFU с записью в собственный `known_hosts` (не трогая пользовательский — `HostKeys.save()` выбросил бы `@cert-authority`) + фикс имени хоста для нестандартного порта (paramiko передаёт уже отформатированное имя, повторная обёртка даёт `[[h]:p]:p` и запись не находится никогда) | votsie | M |
| 1.5 | **Заморозка крипто-алгоритмов** через `transport.disabled_algorithms`: убрать `rsa-sha1`/`ssh-rsa`, `diffie-hellman-group1`, SHA-1 HMAC. Тот же список, что у tufantunc | tufantunc | S |
| 1.6 | **Права на `.env`/`servers.yaml`**: 0600 на POSIX + `icacls /inheritance:r` на Windows (`chmod` на NTFS — защитная бутафория). Сейчас `.env` с паролями в общем доступе | votsie | S |
| 1.7 | **Лестница аутентификации key → agent → password** с накоплением ошибок («пробовали: ...») вместо «всё сразу»; passphrase для paramiko — только байтами | votsie | S |

## Что НЕ брать

| Идея/баг | Почему |
|---|---|
| **Любой код из TheSashaDev/ssh-mcp-server** | **AGPL-3.0**: обяжет к AGPL весь наш сервер. Только идеи, реализация своя |
| `pty: true` на каждом exec | PTY сливает stderr в stdout (секция stderr не появляется никогда), теряются размеры терминала и `env` |
| Пароли в argv / CLI-флагах | tufantunc убрал в v2 как CWE-214 (пароль виден в списке процессов); у нас пароли только в YAML/`.env` |
| `hash()` в имени временного файла фоновой команды | `hash()` для строк рандомизируется на каждый процесс — старый лог осиротеет, возможны коллизии |
| `validate.format(...)` на строке из аргументов | любая лишняя `{}` (`awk '{print $1}'`) либо сломает `.format()`, либо подставит путь |
| `memory._dir(server)` без валидации имени | `ssh_notes_get("a/../../x")` — path traversal; каталог создаётся как побочный эффект чтения |
| Реестр серверов в `.env` с разбором по последнему `_` | жадный регекп рождает фантомные профили (`SSHM_NL1_KEY_FILE` → слаг `NL1_KEY`); у нас строгий YAML с проверкой неизвестных ключей |
| Счётчики вывода, сравнивающие UTF-16 символы с байтовым бюджетом |budget на символы ≠ байты, перелёт на чанк; у нас лимит честный, в байтах |
| Свой `.env`-парсер ради паролей с `#` | у нас пароли приходят из YAML через `${VAR}` и читаются `python-dotenv`, round-trip не нужен |
| PyPI-пакет `ssh-mcp` / `ssh-mcp-server` | это **другие проекты** (czyhandsome, rorymcmahon), не те, что изучались |

## Замечание о конфиге

Ни один из трёх изученных не использует YAML с комментариями: votsie — плоский `servers.env`
(намеренно, «реестр рано или поздно разъезжается»), tufantunc — TOML, TheSashaDev — JSON.
Наш вариант лучше отвечает на исходную задачу («по комментариям понятно, о каком сервере речь»):
`comments` попадают прямо в `ssh_list_servers`. Менять формат не нужно — но стоит
добавить `ssh_guide` (2.10), чтобы агент узнавал про YAML из тула, а не из файла.
